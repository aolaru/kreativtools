PDF fill and sign guide

Use this tool for fixed PDF forms where you need to place visible text, checkboxes, notes, or a signature image without uploading the document to a server.

Best uses

  • Type names, dates, addresses, and short notes onto existing PDF forms.
  • Add a scanned, drawn, or exported signature image to contracts and approvals.
  • Tick simple boxes when the PDF was not built with interactive fields.

How it works

Upload one PDF, choose text, checkbox, or signature mode, then click a page preview to place the item. Drag placed items before generating the final PDF.

Supported files

The source must be a PDF. Signature images can be PNG, JPG, or SVG; SVG signatures are rasterized locally before being placed into the export.

Privacy and limits

The PDF, typed text, checkbox positions, and signature image stay in the browser session. Password-protected or damaged PDFs may fail to load.

Common issues

  • This places overlays; it does not rewrite existing PDF text or form internals.
  • It is not a cryptographic digital-signature or certificate workflow.
  • If the export becomes too large, compress the finished PDF afterward.

Next step

If the final file needs to be smaller, use PDF Compress. If you need to reorder or split pages first, use PDF Merge or PDF Split.

When this becomes repeat work

Need the signed PDF to move through a larger handoff?

PDF Fill & Sign stays free for form overlays. Use PDF Delivery when the same document job also needs queue order, optional splitting, merging, or a final sendable export.

See PDF Delivery Guided in Tools

Example PDF fill and sign jobs

Fixed approval form: add the name, date, checkbox, and signature image, then generate the filled PDF and reopen it once before sending.

Simple contract note: place short text overlays where the existing PDF has blank space. Use a dedicated PDF editor if the source text itself needs to be changed.

Scanned form: use visible text and checkbox overlays for quick completion, then compress the final PDF if the scanned pages make the export too large.

Before you send a PDF

Decide whether the job changes visible content, page order, or file size. Fill and sign before final compression, split before merging if only some pages are needed, and review the exported PDF before sending it to a client, portal, or archive.

PDF work often fails when the final destination is ignored. A portal may care about file size, an approval flow may care about signatures, and a handoff may care about page order. Work backward from that requirement and keep the final downloaded file separate from the original.

  • Keep the source PDF until the export has been checked.
  • Protected or damaged PDFs can fail even when the page loads normally.
  • Compression should be the last step after pages and overlays are final.

After downloading the result, open it once before using it in a client send, upload form, website, or archive. This final check catches format support issues, unexpected file size changes, missing characters, clipped media, or page-order mistakes while the original file is still available.

If the output will be reused, note the settings that produced it. That makes the next export easier to repeat and reduces guesswork when another file needs the same treatment.
